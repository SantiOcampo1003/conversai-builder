# Líneas QR atendidas por el backend (deprecar n8n en WhatsApp) — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que los mensajes de las líneas QR (Evolution) lleguen directo al backend, como ya pasa con la API oficial, y apagar los flujos de n8n de WhatsApp sin cortar la atención.

**Architecture:** Se extrae del `WhatsAppCloudService` un pipeline común ("mensaje normalizado → agente → respuesta por un canal"). Un nuevo webhook `POST /api/evolution/webhook` (protegido con secreto) normaliza el payload de Evolution y usa ese pipeline con un canal Evolution. Las instancias se pasan una por una al webhook nuevo; n8n queda de respaldo hasta verificar y luego se desactiva.

**Tech Stack:** NestJS 11, Evolution API v2 (Baileys), Supabase, OpenAI (transcripción).

**Spec:** acuerdo del usuario: "deprecar n8n y construirlo en nuestro backend con mayor control, performance y estándar" (`docs/superpowers/plans/2026-11-04-evolution-al-backend-y-feedback-en-menu.md`, "Mejora acordada").

1. Descarta `data.key.fromMe`.
2. `SELECT agent_id FROM whatsapp_lines WHERE evolution_instance_name = '<instance>'` — **inyección SQL** (interpolación directa).
3. Texto: `message.conversation` o `message.extendedTextMessage.text`; audio: `messageType === 'audioMessage'` con `message.base64` → Whisper (`whisper-1`, `language=es`).

5. Respuesta vacía → "Disculpa, tuve un problema técnico. ¿Puedes intentar de nuevo? 💛"; `sendText` a Evolution; luego `sendMedia` por cada archivo (`mediatype` image/document).
6. **API key global de Evolution escrita en el nodo** (pendiente de rotar).

## Global Constraints

- Comportamiento visible igual o mejor que n8n: mismos textos de fallo, archivos después del texto, audio transcrito.
- Webhook nuevo protegido: `?secret=<EVOLUTION_WEBHOOK_SECRET>` comparado con `timingSafeEqual`; sin secreto configurado → 403 siempre.
- Responder 200 de inmediato y procesar en segundo plano (Evolution reintenta si tarda).
- Nada de SQL interpolado; nada de llaves en código.
- El corte es **por instancia** y reversible (volver a apuntar el webhook a n8n).
- Tests: `npx jest --no-watchman` verde salvo los 4 conocidos.

## Review Focus

1. Mensajes de **grupos** (`@g.us`), `status@broadcast` y los propios (`fromMe`) → ignorados sin responder.
2. Remitente con **LID** (`…@lid`) → usar `key.remoteJidAlt` / `key.senderPn` si vienen; si no hay número real, responder al mismo `remoteJid` y usar sus dígitos como `userId`.
3. Evolution reenvía el mismo `key.id` → una sola respuesta.
4. Audio sin `base64` (webhook mal configurado) → `AUDIO_FAILED_MESSAGE`, no se llama al agente.
5. Instancia que no está en `whatsapp_lines` o sin agente → se ignora con `warn`, 200 a Evolution.
